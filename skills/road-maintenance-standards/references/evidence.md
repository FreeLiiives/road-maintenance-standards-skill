# 证据与维护流程

## 数据源

自动监测范围由 `data/sources.json` 指定，目前只抓取交通运输部官方 HTML 列表及公告。每次也复查已核对目录的公告。列表内相关标题进入候选库；每轮最多处理 20 个候选详情，优先未访问/较早访问者。列表变更、限流、页面拦截和请求失败会报告，不会删除上次成功记录。

| 用途 | 官方入口 | 自动化状态 |
| --- | --- | --- |
| 行业标准公告 | https://xxgk.mot.gov.cn/zhengceapp/863/894/list_7234.html | 自动 |
| 公路局信息公开 | https://xxgk.mot.gov.cn/jigouapp/741/742/list_6699.html | 自动 |
| 交通标准信息查询 | https://jtst.mot.gov.cn/ | 人工辅助核验 |
| 国家标准全文公开 | https://openstd.samr.gov.cn/ | 人工辅助核验 |
| 全国标准信息公共服务 | https://std.samr.gov.cn/ | 人工辅助核验 |

首版并未完成国家标准、全部省市地方标准、全部历史公告的自动覆盖。需要扩展时先验证官方入口、字段和适用范围，再修改采集器及测试。不能绕过登录、验证码、TLS 校验或访问限制。

## 如何复核候选

1. 打开候选官方公告，区分发布公告、贯彻实施通知、征求意见、计划、解读、修改单、废止公告。
2. 编号与名称以正文为准；保留发布落款日期、网页公开日期、实施日期三个独立字段。旧网页迁移日期不等于标准发布日。
3. 只有正文明确说明时才建立替代/废止关系，关系在指定实施日期生效。名称相近不等于替代。
4. 核对道路类型、管辖地域、路面类型、版本和修订件；全文条款需实际阅读原文并记录章节或页码。
5. 新增/修订 `catalog.json`，补充 `source_url`、`verified_on`、`verification_method`。没有穷尽核验后续公告时保持 `latest_validity` 为 `not_exhaustively_verified`。
6. 运行测试并提交 Git。候选及抓取日志保留作为发现证据，Git 历史用于审计。自动脚本不会赋予“现行”结论。

## 设计参考

Yang, Z., Bi, Y., Wang, L., Cao, D., Li, R. & Li, Q. (2022). *Development and application of a field knowledge graph and search engine for pavement engineering*. Scientific Reports, 12, 7796. DOI: [10.1038/s41598-022-11604-y](https://doi.org/10.1038/s41598-022-11604-y).

论文提供领域知识组织与检索的设计参考。本项目仅实现规范元数据目录、检索词映射、可追溯关系边及增量公告监测；没有复现论文的实体识别训练、实体对齐或完整 KG-Pavement 系统，也没有验证相同实验效果。

## 数据与输出边界

只收录标准标识、日期、官方链接、项目索引词和自编说明；不打包第三方标准全文或训练图片。公告哈希用于发现页面正文变化，不能证明标准文本未变：附件内容变化、单独修订单和列表以外公告仍需单独核验。

按周运行属于周期监测，存在调度和页面发布延迟，不称为实时权威标准库。公开仓库长期不活跃时 GitHub 可能暂停计划运行；到 Actions 页面检查最后一次执行状态。
